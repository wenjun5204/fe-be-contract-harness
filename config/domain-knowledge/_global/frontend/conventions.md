# 前端约定

- 请求层统一从契约派生，不手改生成结果；业务组件通过 hooks 消费请求能力。
- 接口 mock 使用契约派生的 MSW，不手写脱离契约的 mock。
- 状态字段展示必须使用枚举映射，例如 `PENDING` 映射为“待支付”。

## 平台审核合规:四层扫描(实战教训)

合规词表只管「字」是不够的,机审识别是四层的,提审前全量扫描:

1. **字/词层**:运势/吉凶/卦象等违禁词(常规词表)
2. **符号层**:☰☱☲☳☴☵☶☷、☯、🧿 等命理符号同样触发机审——词表最容易漏的就是这层
3. **枚举展示层**:代码里的 Gua/Bagua 枚举名一旦渲染到 UI,等同于命理词;
   展示名与代码枚举分离(如 乾→云鹤),枚举只留在不可见层
4. **命名层**:小程序名称/tabBar 文案/页面标题是审核重点位

**展示层净化模式**:文案问题在前端渲染边界做映射净化,后端枚举/路径/接口
不动(用户不可见不触发审核)——避免为文案返工后端和契约。

## 云托管冷启动:缓存先行(stale-while-revalidate)

微信云托管容器闲置缩容到 0,Java/JVM 服务冷启动常见 5-20s,且首屏常为
登录→拉主数据串行,叠加成白屏。模式:

- 上次成功数据本地缓存,进入先渲染缓存再后台刷新
- "今日"语义的数据(如每日卡片)缓存须带日期,隔天作废
- loading 必须有超时兜底(如 15s→重试入口),防请求悬挂无限转
- 缓存已在屏时网络失败不打断展示(保持内容+轻提示),不推倒重来
