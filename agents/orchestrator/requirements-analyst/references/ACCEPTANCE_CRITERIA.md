# 验收标准编写指南

## Given/When/Then 格式

- **Given**(前置条件):系统处于什么状态
- **When**(触发):用户做了什么操作
- **Then**(预期):可观察的结果

## 质量标准

1. **可测试**:每条标准能被自动化测试验证
2. **明确**:不出现「快速」「友好」等模糊词
3. **独立**:每条标准聚焦一个行为
4. **覆盖边界**:正常 + 异常 + 边界
5. **数量**:每个用户故事 ≥ 3 条

## 正反例

| 反例 ❌ | 正例 ✅ |
|---------|---------|
| 系统响应要快 | Given 数据 1 万条,when 查询,then 响应 < 200ms |
| 页面要好看 | Given 加载完成,when 截图比对,then 与设计稿像素一致 |
| 支持多种排序 | Given 点击「价格」,when 再点,then 升/降序切换 |

## 契约联动(本 harness 特有)

验收标准中涉及字段 / 边界 / 错误码的,后续会映射到 OpenAPI 契约的 `schemas` / `paths` / 错误码,故标准要**可字段化**(如"价格区间 [0, 999999]")。
