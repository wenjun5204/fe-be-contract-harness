# 技术方案评审 Checklist

## 架构合理性
- [ ] 模块划分清晰,职责单一
- [ ] 无循环依赖 / 无过度设计

## 接口设计
- [ ] 接口与契约一致(字段 / 类型 / 错误码)
- [ ] 错误码 / 幂等 / 分页语义明确

## 数据模型
- [ ] 表结构合理,索引充分
- [ ] 老数据兼容策略明确

## 风险
- [ ] 并发 / 一致性 / 降级方案明确
- [ ] 无生产环境风险(写操作无幂等、无事务边界等)

## 反模式(重点拦截)

| 反模式 | 说明 |
|--------|------|
| 过度设计 | 实现未需求的功能 |
| 单体巨石 | 职责不分离 |
| 接口不幂等 | 写操作缺幂等键 |
| 缺降级 | 依赖挂了无兜底 |
| 老数据不兼容 | 字段变更破坏存量 |
