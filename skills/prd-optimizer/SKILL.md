# PRD 优化方法论

> 核心命题：**产品的生死不在功能骨架，在心理引擎。** 骨架（组队/每日任务/提醒/排行榜）谁都能抄，引擎（用户为什么每天回来、为什么转发）才是壁垒。
> 实战样本：`docs/PRD-健康打卡互助团.md`（焦虑引擎，v1 废弃）→ `docs/PRD-全家福接福气.md`（快乐引擎，v2 定稿）。

## 一、五步工作流（按序执行，每步可回溯）

### 1. 人群锚定 —— 先于一切功能

产出 3 个具名画像（姓名/年龄/城市/身份），每个必须写清**心理诉求**而非人口学属性：

- 核心用户（如王阿姨 58：想被子女夸"活得讲究"）
- 付费/拉新用户（如小刘 31：想低成本表达孝心）
- 攀比传播用户（如老陈 63：不服老王家）

反例检查：如果画像只写"45-70 岁三四线用户"，重写——没有心理诉求的画像无法推导功能。

### 2. 心理引擎选择 —— 决定产品生死的一步

用这张表审视候选引擎（来自真实翻车教训）：

| 引擎类型 | 留存 | 传播 | 结论 |
|---|---|---|---|
| 焦虑引擎（健康打卡、监督质问） | 强 | **弱**（没人转发"我又没坚持"） | 能留人，传不开 |
| 快乐/惦记引擎（祝福、为家人做事） | 中 | **强**（转发 = 表达爱与面子） | 传播型首选 |
| 攀比引擎（家族对家族） | 强 | 强 | 传播放大器，需做安全阀（只家族内可见） |

**关键洞察**：质问感文案（"你今天做没做"）→ 授予感文案（"你为家人积福了"）。同一功能骨架，换引擎就是换产品。

### 3. 核心机制设计 —— 每个功能必须能追溯到引擎

- 统一货币（如福值）：**只涨不跌，永不惩罚**（扣分 = 中老年用户卸载）
- 每日仪式：动作有肌肉记忆（摇一摇/翻卡），≤2.5s 动画可跳过
- 稀缺互动：每人每天对每人限 1 次（泛滥即贬值）
- 榜单分层：家内榜（安全攀比）+ 好友榜（家族对家族）
- 等级稀有度（70/25/5）：只影响华丽度，**不影响数值收益**（避免挫败）

### 4. 传播链路设计 —— 转发理由必须显式设计

分享不是功能，是产品的一部分。逐项检查：

- [ ] 转发理由升级了吗？（维护关系 → 为家人做事 → 炫耀 → **好奇心缺口**）
- [ ] 分享卡片标题是钩子吗？（实战模板：「别点这个签…点开就有福!来自{家族名}的家人」——反向命名 + 好奇缺口，与产品名形成闭环）
- [ ] 新用户点开分享落地页，**第一秒就在场景里**吗？（带邀请码直接进家族，不落首页）
- [ ] 攀比可见性做了安全阀吗？（福值仅家族内可见，防社交压力反转）
- [ ] 软引导而非强制？（奖励制 +10，绝不出现"不转发家人会有事"——微信红线）

### 5. 合规与适老化自检 —— 一票否决项

- 禁用词扫描（ grep 检查用户可见文案）：运势/吉凶/求签/算命/占卜/八字/塔罗/改运/挡灾/化解/开光/大师/忌/凶 + 医疗暗示词（降血压/治疗/排毒）
- 只宜不忌、不预测：稀有度玩法不得暗示影响现实
- 适老化硬规范：正文 ≥17pt、主按钮 ≥88rpx、一屏一主按钮、≤3 次点击、零键盘输入优先、文案用「您」、禁英文术语
- 隐私最小化：能用平台静默注入（openid）就不弹授权；新增采集前同步微信隐私指引

## 二、PRD 结构模板（定稿章节）

```markdown
# {产品名} PRD
| 版本/形态/平台/前序文档/状态 |
## 1. 产品概述
  1.1 一句话定位（动词 + 对象 + 机制，如"每天为全家抽一张福卡，全家把福值抬上家族榜"）
  1.2 设计哲学：心理引擎表（引擎/心理机制/对应设计 三列）
  1.3 要解决的问题（用户痛点 × 方案对照表）
  1.4 北极星指标（必须同时衡量留存+传播，如 DBF：当日 ≥2 成员完成抽卡并转发的家庭数）
## 2. 目标用户（3 个具名画像，含心理诉求）
## 3. 核心机制设计（货币表/仪式流程/互动/榜单/门牌）
## 4. 用户旅程（新用户分享进入 → 核心闭环 → 次日回流）
## 5. 传播设计（分享卡片/邀请链路/攀比引擎）
## 6. 数据与指标（北极星 + 过程指标 + 传播系数）
## 7. 合规红线（禁用词表/软引导/隐私）
## 8. MVP 边界（明确不做什么）
```

## 三、迭代模式（从实战提炼）

用户通常多轮反馈，按类型响应：

| 反馈类型 | 动作 |
|---|---|
| "合体/重新设计" | **保留骨架，换引擎**（v1→v2 的核心操作：组队/任务/榜单全留，心理引擎从健康焦虑换祈福快乐） |
| "不好看/主题色不喜欢" | 只动视觉层：中国红 #b01f24 / 描金 #ffd76e / 米黄底 #fff8ec / 福签楷体大字 |
| "要更 low / 要火" | 强化传播钩子：命名好奇心缺口、分享文案反向钩、攀比入口前置 |
| "不太行" | 先问哪一环（引擎/机制/视觉/文案），不要整套推翻 |

## 四、与 fe-be-contract-harness 衔接

- 本 skill 的定稿 PRD 是 **Stage 1（需求分析）的输入**：PRD 定稿后走 harness 全流程，requirements-analyst 把 PRD 结构化为 `requirements_spec`（11 类覆盖 + 契约就绪性）
- 合规词扫描脚本化后可作为 Stage 6 一致性校验的 evidence
- 项目级合规词表与适老化规范应沉淀到目标仓库 `.agents/docs/conventions.md`（harness 会自动进 dispatch context）

## 五、质量自检清单（交稿前过一遍）

1. 每个功能都能追溯到某个心理引擎吗？（不能 = 删或换理由）
2. 北极星指标同时含留存和传播吗？
3. 把自己当王阿姨读分享文案：转发它有面子吗？
4. 焦虑感清零了吗？（质问句全部改授予句）
5. 合规词 grep 通过？「忌」字出现即打回？
6. 新用户 3 次点击内能完成核心动作吗？
7. 命名过"好奇心测试"吗？（听到名字是否产生"这是啥"的冲动，如「别点这个签」）
