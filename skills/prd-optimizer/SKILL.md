# PRD 优化方法论

> 核心命题：**产品的生死不在功能骨架，在心理引擎。** 骨架（组队/任务/提醒/排行榜这类通用模式）谁都能抄，引擎（用户为什么每天回来、为什么转发）才是壁垒。
> 方法论与目标人群/平台无关；领域特定经验（如中老年微信小程序）见 `domain-packs/`，按 PRD 的人群和平台选择加载。

## 第 0 步：定位 PRD 的领域包

开稿前先判断两件事，决定加载哪个领域包（没有匹配的就空手用通用方法）：

- **目标人群**：中老年 / 年轻人 / 职场人 / 家长 / …
- **目标平台**：微信小程序 / 独立 App / Web / …

```text
domain-packs/
└── wechat-senior-miniapp.md   # 中老年人群 × 微信小程序(实战验证:别点这个签)
```

## 〇.五、选题与命名（五步之前的生存判断，2026 选品实战提炼）

五步工作流默认选题已定；选题错了，PRD 写得再好也是给死人化妆。以下四个判断在动笔前完成：

### 1. 真实痛点标尺（三因子乘法，任一为零即出局）

**频率（每天发生 vs 一年一次）× 强度（真难受 vs 忍忍就过）× 现有解法占位（平台空白 vs 官方/竞品已占）**

- 「随礼记账」频率低但怨气浓且无强竞品 → 可做；「个税计算」频率低**且官方 App 已占位** → 只能做差异化（决策器而非计算器）
- 高频但浅（今天吃什么）适合做导流卫星产品，不适合做主打
- 「平台空白」是最值钱的因子：整个产品世界都在帮用户花钱时，「忍住没买」无人认领；竞品都在记数字时，「那天的仪式感」无人经营

### 2. 受众广度与痛点深度成反比

人人有的痛通常浅、可忍、竞品多。广受众工具的赢家不靠赢痛点，靠三件事：

- **年度循环替代每日打开**：纪念日/生日/周年是用户什么都不做也会年复一年回来的唯一结构——解决广受众产品的留存死结
- **晒图传播**：产品产出物本身必须是能引发截图的内容（"在一起第 1000 天"）
- **提醒引擎做护城河**：到期推送是产品价值本身，也是竞品短期抄不走的基建

### 3. 记录型产品的行为错配检验

需要用户「记录」的产品（记账/日记/流水）先回答：**记录行为发生在情绪浓度最高的那一刻，还是事后补记？**

- 「忍住没买」在肾上腺素还在时记 → 成立
- 「周报流水」每天补记没有情绪支撑 → 死；且「愿意每天记的人」和「为周报发愁的人」根本不是同一批用户（目标用户与记录行为错配）
- 诊断句式：谁在记录？谁在消费记录？两者不是同一人时，先证明消费方会开始记录，否则出局

### 4. 小程序命名 = 搜索词策略（血泪：上一版零搜索设计，分享是唯一入口，死了）

**名字不是品牌，搜索词才是品牌**——用户搜「纪念日」不搜你的品牌名。规则：

- **功能词 + 品牌词结构**（如「慢邮纪念日」）：功能词吃搜索流量，品牌词做记忆点与差异化定位
- 简介埋关键词矩阵（每个核心功能词都出现一次）、分享卡片文案带品类词（承接转发场景的二次搜索）
- 品牌词保留反差感/网感（「别点这个签」式缺口），但**不得锁死单一功能**（上一版「全家福」锁家庭场景，后加挂件即别扭）
- 起名后必查重（公众平台后台），备后缀方案（XX局/XX星球）

### 5. 个人主体合规能力边界（选题一票否决项）

个人开发者身份做不了的三条路，选题时直接排除：

| 方向 | 死因 | 依据 |
|---|---|---|
| AI 陪伴/LLM 对话生成 | 需算法备案 + 生成式 AI 备案 | 《生成式人工智能服务管理暂行办法》 |
| 陌生人匹配/扩列/语音房 | 「社交-陌生人交友」类目不对个人开放 | 微信类目资质要求 |
| 公开树洞/广场 UGC | 公开展示需先审后发的内容审核能力 | 网信办内容安全规定 |

纯模板拼装可绕开 LLM 备案（产品力打折，需权衡）；私密存储 + 无公开 feed + 无 AI 生成 = 近乎零风险的缝（如：给未来的自己写信）。

## 一、五步工作流（按序执行，每步可回溯）

### 1. 人群锚定 —— 先于一切功能

产出 3 个具名画像（姓名/年龄/城市/身份），每个必须写清**心理诉求**而非人口学属性：

- 核心用户（谁天天来）
- 付费/拉新用户（谁带来增量）
- 攀比/传播用户（谁把它带给别人）

反例检查：如果画像只写"25-35 岁一线城市用户"，重写——没有心理诉求的画像推导不出功能。心理诉求的标准句式：**"TA 想 ___，但 ___"**（想被认可但没有由头 / 想表达关心但没有抓手）。

### 2. 心理引擎选择 —— 决定产品生死的一步

任何留存+传播型 C 端产品，先填这张表：

| 引擎类型 | 留存 | 传播 | 适用判断 |
|---|---|---|---|
| 焦虑/监督引擎（打卡、质问"你今天做没做"） | 强 | **弱**（没人转发自己的失败） | 能留人，传不开；只适合纯工具 |
| 快乐/情感引擎（祝福、为在乎的人做事） | 中 | **强**（转发 = 表达爱与面子） | 传播型产品首选 |
| 攀比引擎（组 vs 组、家 vs 家） | 强 | 强 | 传播放大器；必须做可见性安全阀 |

**关键转换**：同一功能骨架，把「质问感」文案换成「授予感」文案（"你今天做没做" → "你为 TA 攒了 X"），就是换了引擎、换了产品。

**反直觉经验**：第一版选焦虑引擎几乎是本能（监督、坚持、自律的叙事最"顺理成章"），但焦虑产品的传播是死的——用户转发的是快乐和面子，不是失败。如果初稿是焦虑引擎，优先考虑保留全部骨架、只换引擎。

### 3. 核心机制设计 —— 每个功能必须能追溯到引擎

通用规则（跨人群跨平台成立）：

- **统一货币只涨不跌，永不惩罚**：扣分/清零机制在熟人关系链产品里 = 用户流失（对中老年尤甚，但对所有人群都是负资产）
- **每日仪式感**：动作要有肌肉记忆（摇一摇/翻卡/签到手势），动画 ≤2.5s 且可跳过
- **稀缺互动**：互动类动作每人每天对每对象限 1 次（泛滥即贬值成点赞）
- **分层榜单**：小圈子内榜（安全攀比）+ 大圈子外榜（身份展示），外榜默认最小可见范围 + 隐身开关
- **稀有度设计**（如等级 70/25/5）：只影响华丽度/外观，**不影响数值收益**（避免"抽不到"挫败）
- **每个功能过"引擎追溯"检查**：写不出它服务于哪个心理诉求 → 删掉或改设计

### 4. 传播链路设计 —— 转发理由必须显式设计

分享不是功能，是产品的一部分。逐项检查：

- [ ] 转发理由升级了吗？（维护关系 → 为在乎的人做事 → 炫耀 → **好奇心缺口**）
- [ ] 分享卡片标题是钩子吗？三段式模板：**{好奇心缺口/反差} + {利益点} + {关系来源}**。实战样本：「别点这个签…点开就有福!来自{家族名}的家人」——反向命名制造缺口
- [ ] 命名过"好奇心测试"吗？（听到名字是否产生"这是啥"的冲动；禁忌是描述性命名，如"XX助手""XX管家"）
- [ ] 新用户点开分享落地页，**第一秒就在场景里**吗？（带邀请凭证直达核心场景，不落通用首页）
- [ ] 裂变激励与核心行为一致吗？（拉人入伙的奖励应该强化"人多更好玩"，而非单纯人头数）
- [ ] 攀比可见性做了安全阀吗？（防社交压力反转成卸载理由）
- [ ] 软引导而非强制？（奖励制分享；绝不出现"不转发会有 X 后果"——各大平台的诱导分享红线）

### 5. 平台合规与人群适配自检 —— 一票否决项

通用框架（具体词表/规范从领域包取）：

- **平台红线扫描**：目标平台对品类的敏感词与审核边界（命理/医疗/金融类尤其危险），用户可见文案 grep 扫描
- **道德底线**：可以放大"惦记在乎的人"的情感，**绝不制造恐惧**；文案里的批评语气全部改为召唤语气（"全家在等您"而非"您偷懒了"）
- **隐私最小化**：能用平台静默注入的身份就不弹授权；每新增一项采集，同步平台隐私指引
- **人群适配硬规范**：从领域包取（如中老年 = 大字号/零键盘/≤3 次点击；年轻人群则可能是性能/个性表达优先）

## 二、PRD 结构模板（定稿章节）

```markdown
# {产品名} PRD
| 版本/形态/平台/前序文档/状态 |
## 1. 产品概述
  1.1 一句话定位（动词 + 对象 + 机制，让外行 10 秒复述得出）
  1.2 设计哲学：心理引擎表（引擎/心理机制/对应设计 三列）
  1.3 要解决的问题（用户痛点 × 方案对照表）
  1.4 北极星指标（必须同时衡量留存 + 传播，如"当日 ≥2 名成员完成核心动作并转出的单元数"）
## 2. 目标用户（3 个具名画像，含"想__但__"式心理诉求）
## 3. 核心机制设计（货币表/仪式流程/互动/榜单/成长）
## 4. 用户旅程（新用户分享进入 → 核心闭环 → 次日回流）
## 5. 传播设计（分享卡片/邀请链路/攀比引擎）
## 6. 数据与指标（北极星 + 过程指标 + 传播系数 K）
## 7. 合规红线（平台特定，引用领域包）
## 8. MVP 边界（明确不做什么）
```

## 三、迭代模式（从实战提炼）

用户通常多轮反馈，按类型响应，**避免整套推翻**：

| 反馈类型 | 动作 |
|---|---|
| "合体/重新设计" | **保留骨架，换引擎**（通用模式：组队/任务/榜单全留，心理引擎整体替换） |
| "不好看/主题色不喜欢" | 只动视觉层（色板/字体/圆角密度，从领域包取规范） |
| "要更 low / 要火" | 强化传播钩子：命名好奇心缺口、分享文案反向钩、攀比入口前置 |
| "不太行" | 先问哪一环（引擎/机制/视觉/文案），定位后再动刀 |
| "功能再加点" | 过引擎追溯检查，新功能写不出心理诉求就劝退 |

## 四、与 fe-be-contract-harness 衔接

- 本 skill 的定稿 PRD 是 **Stage 1（需求分析）的输入**：PRD 定稿后走 harness 全流程，requirements-analyst 把 PRD 结构化为 `requirements_spec`（11 类覆盖 + 契约就绪性）

## 五、质量自检清单（交稿前过一遍）

1. 每个功能都能追溯到某个心理引擎吗？（不能 = 删或换理由）
2. 北极星指标同时含留存和传播吗？
3. 把自己当核心画像用户读分享文案：转发它有面子吗？
4. 焦虑感清零了吗？（质问句全部改授予句）
5. 平台红线词 grep 通过？
6. 新用户 3 次点击内能完成核心动作吗？
7. 命名过"好奇心测试"吗？名字里有搜索功能词吗？简介埋了关键词矩阵吗？
8. 记录型功能过了行为错配检验吗？（记录发生在情绪浓度最高时，且记录者=消费者）
9. 选题过了个人主体合规边界表吗？（AI 生成/陌生人社交/公开 UGC 三红线）
10. 领域包的经验用上了吗？（没找到匹配领域包时，考虑把本次沉淀成新的领域包）
