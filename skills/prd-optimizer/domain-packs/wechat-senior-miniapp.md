## 人群心理特征（画像锚定参考）

| 心理特征 | 设计转化 |
|---|---|
| 家人平安 > 一切，为家人做事心甘情愿 | 核心仪式的对象是"全家"而非个人（全家同一张福卡） |
| 转发动机是"维护关系"而非"彰显个性" | 分享物必须精美到"转出去有面子"（替代早安图的升级品） |
| 怕成为子女负担，渴望价值感 | 让长辈有"给晚辈送祝福"的主动角色，不只是被关心方 |
| 有健康焦虑但行动力弱 | 任务藏在奖励里：不做不扣分，做了多攒福（永不惩罚） |
| 同辈攀比是最强传播力 | 家族 vs 家族榜单 + 可晒的门牌/称号 |
| 健康是焦虑不是快乐，焦虑传不开 | **v1 翻车根因**：打卡监督叙事留人传不开，换祈福授予感叙事 |

## 微信平台红线（一票否决）

1. **禁迷信词**（用户可见文案出现即拒审）：运势/吉凶/求签/算命/占卜/八字/塔罗/改运/挡灾/化解/开光/大师/犯太岁/本命/凶/忌。统一用：福卡/福签/祝福/平安/福气/今日宜
2. **只宜不忌**：黄历式内容只输出正面建议，永不出现「忌」和凶吉预测；稀有度只是玩法，不得暗示影响现实
3. **软引导分享**：奖励制（+福值），绝不出现"不转发不生效/家人会有事"式强制恐吓（诱导分享红线）
4. **无医疗暗示**：生活化表述（喝水/散步/泡脚/早睡），禁降血压/降血糖/治疗/理疗/排毒
5. **通知频控**：订阅消息每人每日 ≤4 条；催促类对同一人每日 ≤3 次
6. **类目规避**：选生活服务/社区类目，绝不沾"占卜玄学"类目
7. **隐私最小化**：openid 走云托管 X-WX-OPENID 静默注入；微信昵称头像属于"用户主动提供"，接入前更新用户隐私保护指引

## 适老化 UI 硬规范

- 正文字号 ≥17pt（约 34rpx），核心信息 ≥22pt；主按钮高 ≥88rpx
- 一屏 ≤1 个主按钮；任何功能 ≤3 次点击到达；零键盘输入优先（名称默认生成）
- 文案口语化、用「您」、禁英文术语（"授权"→"允许"，"提交"→"完成"）
- 动画 ≤2.5s 可跳过；每个操作有明确反馈（toast/震动/动画）

## 实战提炼的机制参数（可直接参考）

- 货币体系：个人值（攒）+ 家族池（全家汇入定榜）双层；只增不减
- 行为定价：日抽 +5 / 转发激活 +10 / 附赠任务 +15 / 家人添福 +8（每人每天对每人 1 次）/ 拉人入伙 +30 / 全员连续 7 天 +50
- 稀有度：平安 70% / 如意 25% / 鸿福 5%，只影响卡面华丽度
- 成长阶梯（门牌）：500 / 2000 / 5000 / 20000，只升不降
- 北极星 DBF：当日 ≥2 名成员完成抽卡并转发的家庭数
- 命名实战：「别点这个签」——反向命名制造好奇心缺口；分享标题「别点这个签…点开就有福!来自{家族名}的家人」与产品名闭环

## 技术栈速查（本领域包验证过的组合）

微信云托管（容器 80 端口 + 平台 MySQL 注入）+ Spring Boot cloud profile + `wx.cloud.callContainer`（自动注入 X-WX-OPENID，无需 appid/secret 与 code2session）+ 原生小程序不引 UI 库。部署/踩坑细节见业务仓库 `AGENTS.md`。
